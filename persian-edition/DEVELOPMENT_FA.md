# راهنمای توسعه و ادامهٔ ترجمه

این پروژه **در حال ترجمه** است. ۸ مدخل از ۵۳ مدخل فهرست، پیش‌نویس فارسی دارند. فایل‌های انگلیسی در پوشهٔ نسخهٔ فارسی، محل نگهداری ساختار و خروجی‌های اصلی‌اند؛ کپی‌شدن آن‌ها نشانهٔ ترجمه نیست. وضعیت مرجع در `TRANSLATION_MANIFEST.csv` و `translation_state.json` ثبت می‌شود.

## محیط کاری

از checkout موجود در `/workspace/single-cell-best-practices` و شاخهٔ `persian-translation` استفاده کنید. هر کار ابری از قبل ایزوله است؛ مگر به درخواست صریح کاربر، Git worktree جدید نسازید. ابتدا دستورهای AGENTS.md احتمالی و وضعیت Git را بررسی کنید. فایل‌های اصلی انگلیسی را تغییر ندهید و ترجمه‌های موجود را با نسخهٔ مبدأ جایگزین نکنید.

ابزارهای نصب‌شده در این ماشین:

- محیط Python مجزا: `/workspace/translation-tools`؛ وابستگی‌های مستقیم در `tools/requirements.txt` ثبت شده‌اند.
- Jupyter Book 2.1.6، مطابق نسخهٔ مخزن؛ پیکربندی فعال `myst.yml` است، نه فایل‌های پشتیبان قدیمی `_config.yml` یا `_toc.yml`.
- Pandoc برای ساخت DOCX قابل‌ویرایش از HTML پردازش‌شدهٔ کتاب.
- فونت Noto Naskh Arabic، همراه با اعلان مجوز در `_static/fonts/`.
- قالب رسمی محلی در `/workspace/book-theme`؛ مبدأ `https://github.com/myst-templates/book-theme` و commit مورد استفاده `23f2df5493e23dfb1d9433c8aa64c87beb4232a3` است. وابستگی‌های آن با `npm ci --ignore-scripts --no-audit --no-fund` نصب شده‌اند.
- پشتیبانی پراکسی Node در `/workspace/translation-node` با `global-agent@3.0.0`. TLS و بررسی صحت بسته‌ها غیرفعال نشده‌اند.
- LibreOffice 25.2.3.2 در `/workspace/libreoffice` از بسته‌های رسمی Debian با فهرست امضاشده و بررسی صحت APT آماده شده است. این نصب کاربری است و نصب سیستمی نیست. در یک محیط معمول، نصب LibreOffice Writer از مخزن رسمی توزیع ساده‌تر است.

برای بازسازی محیط Python، یک محیط مجزا ایجاد کنید و `pip install -r persian-edition/tools/requirements.txt` را در آن اجرا کنید. هنگام استفاده از مسیرهای متفاوت، متغیرهای `FA_PYTHON`، `FA_JUPYTER_BOOK`، `FA_LIBREOFFICE_ROOT` و `FA_LIBREOFFICE_PROFILE` را متناسب با نصب خود تنظیم کنید. راه‌اندازی LibreOffice قابل‌حمل این ماشین نیازمند جابه‌جایی مسیر `BRAND_BASE_DIR` در تنظیمات محلی و ایجاد `main.xcd` از فایل پیش‌فرض بسته بوده است؛ داده یا فایل اجرایی برای دورزدن بررسی صحت دستکاری نشده است.

## ساخت آزمایشی

از ریشهٔ مخزن:

```bash
persian-edition/tools/build_preview.sh
```

این دستور فقط خروجی **آزمایشی و ناقص** را می‌سازد. نوت‌بوک‌های علمی اجرا نمی‌شوند؛ از خروجی‌های ذخیره‌شده استفاده می‌شود. کدهای تحلیل و داده‌های علمی حفظ می‌شوند. در نسخهٔ چاپی، آزمون‌های تعاملی به پرسش، گزینه‌ها، پاسخ درست و توضیح‌های قابل‌چاپ تبدیل می‌شوند. کد نوت‌بوک در منبع باقی می‌ماند.

خروجی‌ها:

- `_build/preview-source/_build/html/`: پیش‌نمایش وب.
- `output/preview/Single_Cell_Best_Practices_FA_PREVIEW.docx`: Word آزمایشی قابل‌ویرایش.
- `output/preview/Single_Cell_Best_Practices_FA_PREVIEW.pdf`: PDF آزمایشی با همان صفحه‌آرایی Word.

مبدل PDF، یک ماکروی محلی در پروفایل اختصاصی LibreOffice می‌سازد تا فهرست خودکار Word را به‌روز کند و سپس همان سند را به PDF تبدیل کند. هیچ ماکرویی در فایل DOCX قرار داده نمی‌شود و تنظیمات امنیتی ماکروها کاهش نمی‌یابد. تغییر دستی پروفایل یا سند را پیش از بازسازی حفظ کنید؛ خروجی‌های پوشهٔ `preview` تولیدی‌اند و با اجرای مجدد جایگزین می‌شوند.

برای ساخت قالب آنلاین، دامنهٔ `api.mystmd.org` لازم است. افزودن این دامنه در پیش‌نویس تنظیمات شبکه ذخیره شده، اما ذخیرهٔ پیش‌نویس به معنی اعمال یا انتشار آن نیست. ساخت محلی فعلی از قالب رسمی GitHub استفاده می‌کند. برخی دارایی‌های بیرونی قالب، مانند CSS ریاضی، هنوز برای انتشار نهایی باید از نظر دسترس‌پذیری بررسی شوند.

## کنترل کیفیت و ثبت پیشرفت

```bash
/workspace/translation-tools/bin/python persian-edition/tools/audit.py
/workspace/translation-tools/bin/python persian-edition/tools/check.py
/workspace/translation-tools/bin/python persian-edition/tools/check.py --release
```

دستور آخر اکنون **باید با کد خروج غیرصفر متوقف شود**، زیرا کتاب کامل نیست. موفقیت بررسی حفاظت از مبدأ، به معنی پایان ترجمه یا معتبرشدن طرح‌وارهٔ همهٔ نوت‌بوک‌های مبدأ نیست؛ نتیجه‌ها در گزارش‌های جدا ثبت می‌شوند.

برای ترجمهٔ هر نوت‌بوک، نگاشت صریح سلول‌های Markdown و رشته‌های نمایشی امن آزمون را مانند فایل‌های `translations/` آماده و با `tools/apply_notebook.py` اعمال کنید. این ابزار از ویرایش ثبت‌نشدهٔ ترجمهٔ قبلی جلوگیری می‌کند. تغییر کد محاسباتی، نام‌ها، شناسه‌ها یا خروجی عددی مجاز نیست. سپس manifest، گزارش پیشرفت و کنترل کیفیت را به‌روز و کار را در یک commit معنادار ذخیره کنید.

فایل‌های نهایی با نام‌های بدون `PREVIEW` تنها پس از تکمیل ترجمه و عبور از کنترل انتشار ساخته می‌شوند. در این مرحله چنین فایل‌هایی وجود ندارند.
